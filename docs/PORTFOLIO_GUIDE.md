# AI Digital Teacher Agent｜面试展示与项目讲解

这份指南用于求职、申博、课程答辩或技术交流。目标不是背诵功能列表，而是用一条清晰主线说明：我识别了什么问题、为什么采用 Agent 架构、系统如何形成闭环、工程上解决了哪些真实约束，以及下一步如何评测。

## 30 秒项目介绍

> 我独立设计并实现了一个多模态课堂观察 Agent。浏览器每隔几秒采集一帧课堂画面，后端调用豆包多模态模型得到结构化学生行为，再通过会话状态维护座位连续性、合并重复事件，并只对新出现的异常行为执行语音提醒。课堂结束后，系统会生成逐人事件报告。项目包含 React 工作台、FastAPI 后端、移动端摄像头和音频适配、自动化测试，以及 GitHub Pages 和 Render 部署。

## 3 分钟在线演示

打开：[https://asepochs.github.io/ai-digital-teacher/](https://asepochs.github.io/ai-digital-teacher/)

### 0:00—0:30｜介绍工作台

- 指出这是当前浏览器的真实课堂记录，不是预先填充的全校模拟数据；
- 简要展示实时课堂、AI 分析、事件中心、历史课堂和设置六个页面；
- 强调视觉上是教育管理平台，但核心价值在持续 Agent 工作流。

### 0:30—1:45｜运行实时课堂

1. 上传一张非敏感人物照片作为课堂监督员形象；
2. 点击开始监督并授权摄像头；
3. 展示摄像头画面、模型分析状态、座位检测框和事件时间轴；
4. 说明正常学习只记录，异常行为才进入语音提醒队列；
5. 若使用手机，展示后置摄像头优先和前后镜头切换。

### 1:45—2:30｜解释 Agent 闭环

沿着页面上的一次事件说明：

```text
摄像头帧
  → 豆包多模态推理
  → Pydantic 结构校验
  → 跨帧座位记忆
  → 连续行为合并
  → 异常提醒策略
  → TTS / 浏览器语音
```

关键点：模型负责开放场景理解，确定性程序负责状态、校验、去重与行动边界。

### 2:30—3:00｜结束并复盘

- 点击“结束并生成报告”；
- 展示课堂总结、逐人行为统计和时间轴；
- 到历史课堂说明最近 30 份报告保存在当前浏览器；
- 主动说明模型误判、会话内存和隐私授权等边界。

## 8 分钟技术讲解

### 1. 为什么不是单次视觉 API Demo

单帧识别无法回答“这是同一名学生吗”“行为持续了多久”“刚才是否提醒过”。因此系统需要工作记忆和行动策略，而不仅是模型输出。

### 2. 为什么使用模型 + 状态机

- 多模态模型适合解释开放课堂画面；
- Pydantic 负责把概率性输出压缩成可靠数据契约；
- `LiveSessionState` 负责稳定座位、合并事件和恢复判定；
- 前端语音队列只消费新的异常事件；
- 本地规则报告保证同一事件输入得到稳定结果。

这种混合方式比“让模型控制全部流程”更容易测试、降级和审计。

### 3. 如何保持跨帧连续性

系统不做人脸识别。它优先复用模型给出的已有座位 id，再用检测框中心点距离匹配历史座位。相邻采样中的相同行为会更新原事件持续时间；座位消失超过容忍窗口后再出现，则允许创建新事件并重新提醒。

### 4. 如何处理移动端限制

- `facingMode=environment` 优先请求后置摄像头，并提供逐级降级；
- 开始监督的用户手势同时预热 `HTMLAudioElement` 与 Speech Synthesis；
- 云端 TTS 失败时切换浏览器语音；
- 浏览器仍阻止自动播放时显示显式播放按钮；
- 切换摄像头时暂停采样，避免旧镜头事件污染新画面。

### 5. 如何处理失败

- 单帧模型失败只返回 `degraded`，不会关闭摄像头或终止课堂；
- 每个会话使用异步锁，结束课堂会等待正在处理的最后一帧；
- 视觉模型与 TTS Provider 相互独立；
- 密钥仅在 FastAPI 环境变量中读取，不进入浏览器包；
- GitHub Pages 在发布前执行前端测试和生产构建。

## 可讨论的工程取舍

| 取舍 | 当前选择 | 原因 |
| --- | --- | --- |
| 视频流还是间隔采样 | 约 3 秒采一帧 | 控制 API 成本、带宽和服务限流 |
| 人脸识别还是座位连续性 | 座位位置 | 满足课堂上下文需要，同时降低身份与隐私风险 |
| LLM 报告还是规则报告 | 规则报告 | 输出稳定、可测试，不增加一次模型成本 |
| 服务端数据库还是浏览器历史 | LocalStorage | 适合公开免费演示，减少基础设施复杂度 |
| 云端 TTS 还是浏览器语音 | Provider + fallback | 优先自然语音，同时保证降级可用 |

## 求职讲解重点

面向前端或全栈岗位：

- 教育 SaaS 信息架构和响应式组件设计；
- 摄像头生命周期、页面切换保持视频流和资源清理；
- 异步请求、错误状态、语音队列和本地历史；
- API 数据契约、自动化测试与持续部署。

面向 AI Agent 或后端岗位：

- 多模态模型结构化输出与防御性解析；
- 会话短期记忆、事件合并与确定性行动策略；
- Provider 抽象、超时、降级和密钥边界；
- 模型能力与程序控制之间的职责划分。

## 申博或研究交流重点

可以把项目定义为“面向人机协同课堂观察的多模态 Agent 原型”，重点讨论：

- 连续课堂状态理解，而不是孤立图像分类；
- 行为识别误报对人类用户信任和课堂干扰的影响；
- 提醒频率、可解释性与教师复核之间的平衡；
- 无身份识别条件下的位置连续性；
- 未来如何建立人工标注集和定量评测协议；
- 隐私、知情同意和高影响教育决策的治理边界。

不要把当前系统表述为已经证明能提升学习成绩，也不要声称识别准确率达到某个未经评测的数据。

## 常见问题与建议回答

### 为什么称为 Agent，而不是普通 AI 应用？

因为它不是把一张图交给模型后直接显示答案，而是在会话中持续感知环境、保留短期状态、依据策略决定是否行动，并把行动结果沉淀为报告。模型推理只是闭环中的一个环节。

### 为什么不用 YOLO 等专用视觉模型？

当前阶段优先验证开放课堂行为的产品闭环，多模态模型能用较少训练数据覆盖更丰富语义。若进入真实部署，应采集合规数据，对高频行为训练或微调专用模型，再由多模态模型处理长尾解释。

### 如何证明系统有效？

当前自动化测试证明的是软件逻辑，而不是视觉准确率。下一步应建立经人工标注的视频片段集，分别评估行为分类精确率/召回率、检测框 IoU、跨帧座位稳定率、重复提醒率和端到端延迟。

### 最大技术风险是什么？

第一是开放场景视觉误判，第二是移动浏览器权限和自动播放限制，第三是免费实例的冷启动与无持久化。项目通过人工复核定位、音频降级、明确状态提示和本地报告历史降低这些风险，但没有假装完全消除它们。

### 如果要部署到学校，下一步是什么？

增加账号、学校/班级/角色权限、PostgreSQL、对象存储、审计日志、数据保留策略和可观测性；完成真实设备与网络压测，并在伦理审查、授权与隐私制度下建立评测集。
