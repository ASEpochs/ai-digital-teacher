# 课堂观察工作区：界面设计与验证

## 本次审查

2026-09-20 对线上六个页面及 React 组件、摄像头、音频和会话状态代码进行审查。原界面的主要问题是：

- 首屏宣传横幅与装饰插画占用空间，课堂准备和设备状态出现在较下方；
- 首次使用时，多个零值指标和空图表增加了阅读负担；
- 存在没有操作意义的英文小标题与宣传文案；
- 辅助文字大量使用 8～11px，浅色文字的阅读对比不足；
- 实时画面、监督员设置和观察结果之间的任务顺序不够明确；
- 事件列表难以逐列比较时间、座位、风险与提醒方式；
- 后端连接状态不能说明视觉模型是否配置，需要分别呈现。

## 页面组织

页面按“准备课堂 → 实时观察 → 检索事件 → 分析报告 → 历史归档”的操作顺序组织。保留原 Hash 路由与 GitHub Pages 子路径兼容性。

| 页面 | 当前组织方式 |
| --- | --- |
| 工作台 | 学校、教室、课程、观察员、当前会话、主要操作与服务检查；首次使用展示四步准备流程；使用后展示真实统计与最近课堂 |
| 实时课堂 | 桌面以视频为主，约 70% / 30% 分栏；右侧合并监督员语音与当前观察；事件时间轴独立折叠 |
| 事件中心 | 正常/异常筛选、关键词检索与表格；显示时间、座位、行为、持续时间、风险与提醒方式 |
| AI 课堂分析 | 空白会话只显示操作入口；完成课堂后先显示摘要、逐人记录，再显示行为统计 |
| 历史课堂 | 搜索、会话状态、逐行报告入口和 JSON 导出；明确本机保存范围 |
| 工作区设置 | 课堂信息表单、课堂服务与视觉模型分别检查、设备使用说明 |

手机首次使用时先展示监督员照片设置，再展示视频和观察结果；完成照片设置后，视频排在最前。通过 CSS 调整顺序，避免重新挂载视频元素。

## 组件与样式

- `Shell`：浅色导航、课堂上下文、观察员信息与移动菜单。菜单提供 Escape 关闭、键盘焦点约束与返回。
- `Dashboard`：根据真实历史与当前会话切换准备界面和数据界面。
- `ServiceHealth`：统一展示课堂服务、模型配置状态和重试入口。
- `LiveClassroom`：摄像头画面、检测框、字幕、控制与折叠时间轴。
- `TeacherControls`：上传照片、测试语音和手动播放降级。
- `EventsPage` / `HistoryPage`：共用列表工具栏与表格视觉规范。
- `Analysis` / `ReportView`：按阅读顺序呈现摘要、学生记录、行为统计。
- `ui`：统一按钮、状态、面板、指标和空状态。

旧欢迎横幅、装饰插画、环形图、无数据趋势图及其样式已移除。使用系统中文字体；正文基准 14px，辅助内容 12～13px，页面标题 24px，模块标题 16px。深蓝用于信息层级，青绿用于主要操作，琥珀与红色用于关注状态。采用 4～6px 圆角、细分隔线，不使用装饰阴影、渐变与发光。

布局覆盖 1920×1080、1440×900、1366×768 与 390px 手机宽度。宽表格在自身容器内滚动，不撑开页面。保留键盘焦点、移动端较大输入字号、媒体内联播放与减少动画设置。

## 功能和数据边界

`useClassroom`、摄像头请求策略、移动端音频解锁、API 路径和会话状态逻辑保持原样。实时视频始终挂载，非实时页面通过 `hidden` 隐藏。切换页面不结束课堂；结束观察关闭轨道并归档报告。

- 无记录时不展示零值统计和空图表；
- 今日统计只覆盖当前浏览器的已结束课堂与当前会话；
- 正常记录占比按事件条数计算，不等于专注度或教学质量评分；
- 分析次数包含成功与未完成的分析尝试；
- 识别人数不是考勤人数；
- 模型“已配置”来自服务配置检查，不承诺外部模型请求必定成功；
- 异常事件显示“进入语音流程”，不虚构实际播放成功或人工处理状态；
- 本机保存最多 30 份已结束报告，不支持账号或跨设备同步。

## 验证

- 前端单元测试 23 项：摄像头回退、移动端音频、事件筛选、数据口径、本机存储容错、首次使用准备与模型配置状态。
- 后端回归测试 21 项：会话状态、连续事件合并、结构化分析、报告、上传与 TTS 接口。
- 六页面 × 四种视口：检查导航、横向溢出、控制台错误和实际页面截图。
- 受控浏览器流程：上传照片 → 正常记录不请求语音 → 新异常提醒 → 连续异常去重 → 恢复后再次提醒 → 暂停/继续 → 镜头切换 → 跨页保持摄像头 → 结束生成报告 → 关闭媒体轨道 → 归档 → 刷新回看 → JSON 导出。
- 移动端导航检查：打开焦点、Tab 循环、Escape 关闭与焦点返回。
- 移动端语音降级：模拟自动播放受阻，点击手动播放后恢复提醒。
- 生产构建及 GitHub Pages 发布检查。

浏览器流程测试使用模拟视频流和测试接口，数据只存在于隔离的测试浏览器中，不写入生产页面。自动化检查不代替真实 iOS/Android 设备的摄像头、扬声器与系统权限验收，也不评估云端模型识别准确率。
